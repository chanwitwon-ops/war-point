# Battle Animation Test (scratch tool — not part of the docs/ pipeline)

เครื่องมือทดลอง pipeline อนิเมชั่นของกลไกต่อสู้ระยะไกล (ง.๑ ใน `20260821-02-pet-points-and-weekly-arena.md`) — **ไม่ใช่ prototype ตามความหมายของ `DESIGN.md`** (ไม่ผ่าน skill `build-prototype`, ไม่ยึดกฎ self-contained/inline-SVG) จึงแยกไว้นอก `docs/02-design/01-prototypes/` โดยเจตนา เพื่อไม่ให้ audit ของสายเอกสารมาตรวจแล้วฟ้องผิดกฎ

เปิดดูได้โดยรันเว็บเซิร์ฟเวอร์ใดก็ได้ที่รากโปรเจกต์ (เช่น `static-server.ps1` ที่มีอยู่แล้ว) แล้วเข้า `experiments/battle-animation-test/battle-test.html` — **ต้องเปิดผ่าน http:// เท่านั้น** (ไฟล์วิดีโอโหลดผ่าน `fetch()` เป็น blob URL เพื่อความเร็ว จะพังถ้าเปิดแบบ `file://`)

## สถานะปัจจุบัน (2026-09-04)

**กลไกที่ยืนยันแล้วว่าใช้ได้จริง:**
- ระบบ chroma-key ลบพื้นหลังแบบ real-time ผ่าน canvas (`keyAlpha`/`chromaKeyDraw`)
- โหลดคลิปเป็น blob URL ล่วงหน้าทั้งไฟล์ (`toBlobUrl`) แก้ปัญหา seek ช้า/เฟรมค้าง
- ตรรกะ hit/miss/หลบ/ดาเมจ/ผลัดเทิร์น (`doTurn`) — สุ่มผลก่อนยิงเสมอ ให้ท่าทาง/การเคลื่อนที่สอดคล้องกับผลจริง
- ทิศทางท่าหลบ (`mirrorForClip`) พลิกอัตโนมัติให้หลบออกจากคู่ต่อสู้เสมอ ไม่ว่าอยู่ฝั่งไหน

**การเปลี่ยนทิศทางล่าสุด (2026-09-03, ดู log วันเดียวกัน):** เลิกใช้ "ยิงข้ามจอแนวนอน" ทั้งหมด เปลี่ยนเป็น **"ยิงขึ้นฟ้า → พลังงานร่วงลงมาใส่เป้าหมาย"** (แนวตั้ง) ให้เข้ากับรูปแบบเดียวกับที่ Behemoth จะใช้ (ทุบพื้นให้หินร่วงจากบน) — `fireProjectile` ถูกเขียนใหม่ให้เคลื่อนที่แนวตั้ง (`top`) แทนแนวนอน (`left`) แล้ว และ**ตรรกะ hit/miss ง่ายลง** เพราะของที่ตกจากฟ้าจะตกที่ตำแหน่งเดิมเสมอไม่ว่าจะโดนหรือไม่ (ไม่ต้องมี "หยุดที่ขอบ vs ทะลุผ่าน" แบบตอนเป็นแนวนอนอีกต่อไป)

## คลิปใน `clips/` — อันไหนพร้อมใช้จริง อันไหนเป็นแค่ placeholder

| ไฟล์ | สถานะ | หมายเหตุ |
|---|---|---|
| `idle.mp4` | ⚠️ ใช้ได้แต่ควรแทนที่ | จริงๆ คือคลิปร่ายเวทที่ล้มเหลวรอบแรกที่เอามารีไซเคิล คทายังเรืองแสงค้าง (ไม่ใช่ปัญหาการทำงานของระบบ แค่ไม่ตรงตามหลักการ "ให้ลูกพลังงานเป็นเจ้าของแสงที่เดียว" ที่ตัดสินใจไว้ล่าสุด) |
| `dodge.mp4` | ✅ ผ่านแล้ว | สี/ทิศทาง/ไม่มีเอฟเฟกต์แถม ยืนยันแล้ว — `CLIP_START_OFFSET.dodge = 1.6` คือช่วงที่ต้องข้ามไปก่อนถึงจังหวะหลบจริง |
| `hit.mp4` | ✅ ผ่านแล้ว | พื้นหลังแบนราบ ไม่มีไล่เฉด ยืนยันแล้วในเกมจริง |
| `cast.mp4` | ❌ **ของเก่า รอเปลี่ยน** | เป็นคลิป "ยกคทาไปข้างหน้าแล้วเรืองแสง" แบบเดิมที่เลิกใช้แล้ว — กำลังรอคลิปใหม่ "เงยหน้ายิงฟ้า ไม่มีแสง" (สร้างผ่านเทคนิค start/end frame บน Kling AI ที่กำลังทำอยู่) เมื่อได้ไฟล์จริงแล้ว **ต้องลบ `cast: 2.2` ออกจาก `CLIP_STOP_AT` ไปแล้ว (ทำไปแล้วในรอบนี้) และเช็คว่าไม่ต้องเพิ่มค่าอื่นสำหรับคลิปใหม่** |
| `projectile.mp4` | ❌ **ของเก่า รอเปลี่ยน** | เป็นคลิปลูกแก้วบิน**แนวนอน** จากยุคก่อนเปลี่ยนทิศทาง — ใช้เป็น placeholder ชั่วคราวสำหรับทดสอบโค้ดแนวตั้งเท่านั้น (หน้าตาจะดูแปลกเพราะเป็นคลิปแนวนอนที่ถูกบังคับให้เคลื่อนที่แนวตั้งแทน) ต้องรอคลิป "ของหล่นจากฟ้า" ตัวจริง แล้วอาจต้องปรับ `PROJ_SRC_RECT` (ตำแหน่ง crop ในเฟรม) ใหม่ให้ตรงกับเฟรมของคลิปใหม่ |

## งานที่เหลือ (รอโควต้า AI tool รีเซ็ต)

1. คลิป "เงยยิงฟ้า" ใหม่ (แทน `cast.mp4`) — กำลังทำผ่าน Kling AI (start/end frame technique) ยังไม่เสร็จตอนบันทึกไฟล์นี้
2. คลิป "ของหล่นจากฟ้า" ใหม่ (แทน `projectile.mp4`) — ยังไม่ได้เริ่ม พรอมต์เตรียมไว้แล้ว (ดูบทสนทนา/log ของวันที่ 2026-09-03/04)
3. พิจารณาทำ `idle.mp4` ใหม่ให้ไม่มีแสงเลย (ความสำคัญลดลงหลังเปลี่ยนเป็นแนวตั้ง เพราะตัวละครไม่จำเป็นต้องมีแสงที่ตัวเองอีกต่อไปในการยิง แต่ยังดูไม่สอดคล้อง 100% ถ้าคทาเรืองแสงตลอดเวลาโดยไม่มีเหตุผล)
4. เมื่อคลิปใหม่มาแล้ว ต้อง**วัดจังหวะจริงใหม่** (ไม่ใช่เดา) ว่าต้องตั้ง `CLIP_START_OFFSET`/`CLIP_STOP_AT` ใหม่ไหม เหมือนที่ทำกับ `dodge.mp4` ก่อนหน้านี้ (ใช้ ffmpeg แตกเฟรมดูจริง)

หลังจากทำครบ Pixie แล้ว ค่อยไปทำ Behemoth/สายอื่นด้วย pattern เดียวกัน (ทุบพื้น → หินร่วงจากฟ้า) ตามที่ตัดสินใจไว้
