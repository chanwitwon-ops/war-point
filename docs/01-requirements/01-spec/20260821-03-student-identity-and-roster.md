## บริบท / ที่มา

- เอกสารนี้ปิดช่องว่างที่ทั้ง `20260821-01-lesson-and-quiz-system` และ `20260821-02-pet-points-and-weekly-arena` ประกาศไว้ตรงกันว่า "ระบบล็อกอินและการจัดการรายชื่อนักเรียน" อยู่นอกขอบเขตของตน จึงยังไม่มีเอกสารใดครอบเรื่องนี้เลย ทั้งที่ไม่มีระบบตัวตนก็ใช้ฟีเจอร์อื่นไม่ได้
- บริบท: นักเรียนประถม 1 ห้อง ประมาณ 30 คน ส่วนใหญ่**ไม่มีอีเมลของตัวเอง**, ครู 1 คน, ต้องใช้ได้ทั้งมือถือที่บ้านและแท็บเล็ต/คอมพิวเตอร์ของโรงเรียน

## ความต้องการ (Requirement)

### ก. การล็อกอินของนักเรียน

- นักเรียนล็อกอินด้วย **รหัสประจำตัว + PIN ที่เป็นตัวเลข**
- เหตุผล: เด็กประถมจำตัวเลขได้ง่ายกว่าตัวอักษร และส่วนใหญ่ไม่มีอีเมลของตัวเอง
- **ครูรีเซ็ต PIN ให้นักเรียนได้เมื่อเด็กลืม**
- ใช้ล็อกอินได้ทั้งที่โรงเรียนและที่บ้าน
- **นักเรียนต้องเปลี่ยน PIN ในการล็อกอินครั้งแรก** เพราะ PIN ที่ระบบสร้างมีคนอื่นเห็นจากใบแจก
- **ระบบล็อคการล็อกอินชั่วคราวเมื่อกรอก PIN ผิดหลายครั้ง** เพื่อกันเด็กเดา PIN ของเพื่อนแล้วสวมรอย ซึ่งกระทบความเป็นธรรมของคะแนนโดยตรง — **ครูปลดล็อกให้ได้**
- **ยังไม่กำหนดจำนวนครั้งที่กรอกผิดได้และระยะเวลาที่ล็อค** (ดู Open Questions)

### ข. การล็อกอินของครู

- ครูล็อกอิน **ด้วยบัญชี Google**
- เหตุผล: ครูไม่ต้องจำรหัสผ่านเพิ่ม และปลอดภัยกว่าการให้ระบบเก็บรหัสผ่านเอง
- **ถ้าโรงเรียนไม่ได้ออกบัญชี Google ให้ ครูใช้บัญชี Google ส่วนตัวได้** เพราะครูไทยส่วนมากมีบัญชีอยู่แล้ว จึงไม่ติดเงื่อนไขว่าโรงเรียนต้องออกบัญชีก่อน
- **ความเสี่ยงที่บันทึกไว้:** เมื่อครูใช้บัญชีส่วนตัว ข้อมูลห้องเรียนจะผูกกับบัญชีส่วนตัวของครู ไม่ใช่บัญชีที่โรงเรียนควบคุม ซึ่งเป็นประเด็นที่ต้องพิจารณาเมื่อขยายเกินรอบทดลอง

### ค. การเพิ่มรายชื่อนักเรียนเข้าระบบ

**รหัสประจำตัว:**
- **ใช้รหัสประจำตัวของโรงเรียนเสมอ** ทั้งกรณีนำเข้าจากไฟล์/ลิงก์ (ใช้รหัสที่มีอยู่ในไฟล์/ชีท) และกรณีเพิ่มทีละคน (ครูกรอกรหัสของโรงเรียนเอง) — ระบบไม่สร้างรหัสประจำตัวขึ้นเอง เพื่อให้ครูเทียบกับสมุดรายชื่อของตนได้ทันที และเด็กก็จำรหัสที่ตัวเองมีอยู่แล้วได้
- **ระบบสร้างเฉพาะ PIN เริ่มต้นให้อัตโนมัติ** ครูไม่ต้องคิด PIN เอง แล้วพิมพ์ใบแจกให้เด็กได้ (แก้ไขความคลาดเคลื่อนของเวอร์ชันก่อนหน้าที่เขียนกำกวมว่า "ระบบสร้างรหัส+PIN")

**ช่องทางนำเข้ารายชื่อ — ต้องยืดหยุ่นรองรับได้ทั้ง 2 ทาง:**
1. **อัปโหลดไฟล์** — รองรับทั้ง Excel และ CSV
2. **วางลิงก์ Google Sheets** — ครูไม่ต้องดาวน์โหลดไฟล์ก่อน สอดคล้องกับที่ครูล็อกอินด้วยบัญชี Google อยู่แล้ว

นอกจากนี้ยังมี **การเพิ่มทีละคนด้วยมือ** สำหรับกรณีมีนักเรียนย้ายเข้ากลางเทอม โดยครูกรอกรหัสประจำตัวของโรงเรียนเอง เช่นเดียวกับสองทางข้างต้น

**ทั้งการอัปโหลดไฟล์และการวางลิงก์ Google Sheets ใช้กลไกเดียวกัน:**
- **ครูเป็นผู้เลือกเองว่าคอลัมน์ไหนคือรหัสประจำตัวนักเรียน** ระบบไม่บังคับให้ครูจัดไฟล์ใหม่ตามแบบของระบบ เพราะการบังคับจัดไฟล์ใหม่คือการเพิ่มภาระครู
- **ระบบจับคู่ข้อมูลด้วยรหัสประจำตัวนักเรียนเท่านั้น**
- **ระบบนำเข้าเฉพาะคอลัมน์รหัสประจำตัว ไม่บันทึกชื่อจริงลงระบบ** ไม่ว่าจะมาจากไฟล์หรือจากลิงก์ Google Sheets

**สิ่งที่ผู้ใช้ไม่ได้เลือก:** ให้นักเรียนสมัครเองแล้วครูอนุมัติ — จึงไม่มีในระบบ

### ง. ข้อมูลของนักเรียนที่ระบบเก็บ

- ระบบเก็บ **รหัสประจำตัว + ชื่อเล่น + เวลาที่นักเรียนเข้าใช้งานล่าสุด เท่านั้น ไม่เก็บชื่อ-นามสกุลจริง**
- เหตุผล: เก็บเท่าที่จำเป็นเพื่อลดความเสี่ยงด้านข้อมูลส่วนบุคคลของเด็กให้ต่ำที่สุด ครูสามารถเทียบรหัสประจำตัวกับสมุดรายชื่อของตนเองได้อยู่แล้ว
- **การอัปโหลดไฟล์รายชื่อต้องนำเข้าเฉพาะรหัสประจำตัว ไม่บันทึกชื่อจริงลงระบบ** แม้ไฟล์ต้นทางของครูจะมีชื่อจริงอยู่ก็ตาม
- **เวลาที่นักเรียนเข้าใช้งานล่าสุด:** เก็บเป็น**ค่าล่าสุดค่าเดียว ไม่เก็บประวัติการเข้าใช้งานทั้งหมด** เพื่อลดข้อมูลของเด็กให้น้อยที่สุดตามหลักเดียวกัน เหตุผลที่ต้องเก็บ: [[20260821-04-teacher-class-overview|20260821-04-teacher-class-overview]] ต้องใช้ข้อมูลนี้เพื่อให้ครูเห็นว่าเด็กคนใดหายไป

### จ. ชื่อเล่นของนักเรียน

- **นักเรียนตั้งชื่อเล่นเอง** เพราะเด็กจะรู้สึกเป็นเจ้าของ และครู 1 คนไม่ต้องมานั่งตั้งชื่อให้ 30 คน
- **ระบบกรองคำหยาบอัตโนมัติ** ปฏิเสธชื่อที่ไม่เหมาะสมตั้งแต่ตอนตั้ง
- **ครูล้างชื่อเล่นได้** เป็นชั้นป้องกันสำรอง เพราะการกรองอัตโนมัติไม่ครอบคลุมทุกกรณี

### ฉ. นักเรียนย้ายออกกลางเทอม

- **ปิดการใช้งานบัญชี แต่เก็บข้อมูลไว้ ไม่ลบ** — เด็กที่กลับมาเรียนต่อได้ข้อมูลเดิมคืน และสอดคล้องกับหลักที่ว่าแต้มสะสมไม่มีวันลด
- บัญชีที่ปิดใช้งานต้องไม่ปรากฏในรายการที่ครูใช้งานประจำวัน

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** การล็อกอินของนักเรียนด้วยรหัสประจำตัว+PIN, การรีเซ็ต PIN โดยครู, การล็อกอินของครูด้วยบัญชี Google, การเพิ่มรายชื่อทั้ง 3 ทาง, การสร้าง PIN เริ่มต้นอัตโนมัติ, ขอบเขตข้อมูลนักเรียนที่เก็บและไม่เก็บ
- **ไม่อยู่ในขอบเขต:** ระบบบทเรียนและแบบทดสอบ (อยู่ใน `20260821-01-lesson-and-quiz-system`), ระบบสัตว์เลี้ยง/แต้ม/การแข่งขัน (อยู่ใน `20260821-02-pet-points-and-weekly-arena`), การส่งออกคะแนนเข้าสมุดคะแนนของครู — **[อัปเดต 2026-08-21] ย้ายเข้ามาอยู่ในขอบเขตของโปรเจกต์แล้ว** ดู `[[20260821-05-score-export-and-gradebook|20260821-05-score-export-and-gradebook]]` · ส่วนที่ยังอยู่นอกขอบเขตจริงคือการส่งคะแนนเข้าระบบทะเบียนกลางของโรงเรียนหรือของกระทรวงโดยตรง, บัญชีและหน้าจอสำหรับผู้ปกครอง, การรองรับหลายห้องเรียนหรือหลายโรงเรียน

## Acceptance Criteria

- [ ] นักเรียนล็อกอินได้ด้วยรหัสประจำตัวและ PIN ที่เป็นตัวเลข โดยไม่ต้องใช้อีเมล
- [ ] ครูรีเซ็ต PIN ของนักเรียนรายคนได้
- [ ] ครูล็อกอินได้ด้วยบัญชี Google โดยระบบไม่เก็บรหัสผ่านของครู
- [ ] ครูนำเข้ารายชื่อทั้งห้องจากไฟล์ได้ในครั้งเดียว
- [ ] ครูเพิ่มนักเรียนทีละคนได้
- [ ] ระบบสร้าง PIN เริ่มต้นให้โดยครูไม่ต้องคิดเอง
- [ ] ฐานข้อมูลของระบบไม่มีชื่อ-นามสกุลจริงของนักเรียนอยู่เลย แม้ครูจะอัปโหลดไฟล์ที่มีชื่อจริงเข้ามา
- [ ] นักเรียนล็อกอินได้ทั้งบนมือถือและบนจอขนาดใหญ่
- [ ] ไม่มีขั้นตอนใดที่ต้องให้ผู้ปกครองสมัครบัญชีหรือเข้าใช้ระบบ
- [ ] นักเรียนถูกบังคับให้เปลี่ยน PIN ในการล็อกอินครั้งแรก
- [ ] ระบบล็อคการล็อกอินชั่วคราวเมื่อกรอก PIN ผิดหลายครั้ง และครูปลดล็อกได้
- [ ] ครูล็อกอินได้ด้วยบัญชี Google ส่วนตัวโดยไม่ต้องมีบัญชีที่โรงเรียนออกให้
- [ ] ครูนำเข้ารายชื่อได้ทั้งจากไฟล์ Excel, CSV และจากลิงก์ Google Sheets
- [ ] ครูเลือกได้เองว่าคอลัมน์ไหนคือรหัสประจำตัว โดยไม่ต้องจัดไฟล์ใหม่ตามแบบของระบบ
- [ ] รหัสประจำตัวที่ระบบใช้เป็นรหัสของโรงเรียน ระบบไม่สร้างรหัสขึ้นเอง
- [ ] ระบบเก็บเวลาเข้าใช้งานล่าสุดของนักเรียนเป็นค่าเดียว ไม่เก็บประวัติทั้งหมด
- [ ] นักเรียนตั้งชื่อเล่นเองได้ ระบบปฏิเสธชื่อที่ไม่เหมาะสม และครูล้างชื่อเล่นได้
- [ ] นักเรียนที่ย้ายออกถูกปิดการใช้งานโดยข้อมูลไม่ถูกลบ และไม่ปรากฏในรายการที่ครูใช้ประจำวัน
