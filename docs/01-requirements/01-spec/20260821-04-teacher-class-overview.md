## ความต้องการ (Requirement)

### ก. ข้อมูลที่หน้านี้ต้องแสดง

ผู้ใช้เลือก 3 อย่าง:
1. **ใครทำแบบทดสอบแล้ว / ใครยังไม่ทำ** แยกตามแต่ละชุด
2. **คะแนนรายคน**
3. **ใครไม่เข้าใช้งานระบบนานแล้ว** เพื่อให้ครูตามเด็กที่หายไปได้ก่อนจะสายเกินไป

แสดงตัวนักเรียนด้วย **รหัสประจำตัวและชื่อเล่น** เท่านั้น เพราะระบบไม่เก็บชื่อจริง

### ข. ข้อมูลที่หน้านี้ **จงใจไม่แสดง** — พร้อมเหตุผล

**หน้านี้ไม่แสดงแต้มหรือขั้นการเติบโตของสัตว์เลี้ยงของนักเรียน** ผู้ใช้ตัดสินใจเรื่องนี้อย่างชัดเจนพร้อมเหตุผล ให้บันทึกไว้ตามนี้:

- ครูไม่จำเป็นต้องรับรู้เรื่องสัตว์เลี้ยงของนักเรียน ถ้าครูต้องมานั่งดูว่าใครอยู่ขั้นไหนแล้วเรียงว่าใครสูสีกับใคร ระบบจะกลายเป็น**เพิ่ม**ภาระครูแทนที่จะ**ผ่อน**ภาระ ซึ่งขัดกับข้อจำกัดหลักของโปรเจกต์
- การจับคู่แข่งขันจะใช้วิธีให้**นักเรียนเลือกเองว่าอยากสู้กับใคร** แทนที่จะให้ครูจับคู่ตามระดับ
- **หลักการออกแบบที่ผู้ใช้ระบุ:** *"เราไม่ได้ต้องการความเท่าเทียม แต่เรากำลังส่งเสริมให้เด็กอยากขึ้นไปเท่าเทียมกับเพื่อน"* — การเห็นเพื่อนที่แข็งแรงกว่าคือแรงจูงใจ ไม่ใช่ปัญหาที่ต้องกำจัดด้วยการจับคู่ให้สูสี

### ค. การเตือนครูเชิงรุก

- **มีสัญลักษณ์เตือนแสดงบนแถวของนักเรียนที่ครูควรดูแล** ครูกวาดตาเห็นได้ทันทีโดยไม่ต้องไล่อ่านตัวเลขทีละแถว
- ระบบไม่ส่งการแจ้งเตือนออกไปนอกระบบ (ไม่รบกวนครูนอกเวลาที่ครูเลือกเข้ามาดูเอง)

### ง. การทำงานต่อจากหน้านี้

- **ครูกดจากแถวของนักเรียนแล้วทำงานต่อได้เลย** เช่น ไปตรวจใบงาน บันทึกคะแนน หรือรีเซ็ต PIN
- เหตุผล: ลดการสลับหน้าไปมา ซึ่งเป็นการลดเวลาที่ครูต้องใช้จริง

### จ. การเรียงลำดับและการกรอง

- **ครูเลือกวิธีเรียงและกรองข้อมูลเองได้** เช่น เรียงตามคะแนน เรียงตามคนที่ต้องดูแล หรือกรองเฉพาะคนที่ยังไม่ส่งงาน
- เหตุผล: ครูแต่ละคนใช้งานต่างสถานการณ์กัน ระบบไม่ควรบังคับลำดับเดียว

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** การแสดงสถานะทำ/ไม่ทำแบบทดสอบรายชุด, คะแนนรายคน, การแสดงคนที่ไม่เข้าใช้งานนาน, สัญลักษณ์เตือนบนแถว, การกดจากแถวไปทำงานต่อ, การเรียงและกรองที่ครูเลือกเอง, การแสดงตัวนักเรียนด้วยรหัสประจำตัวและชื่อเล่น
- **ไม่อยู่ในขอบเขต:** การแสดงแต้มหรือขั้นสัตว์เลี้ยงของนักเรียน (จงใจไม่ทำ ดูเหตุผลข้อ ข.), การจับคู่แข่งขัน (อยู่ใน `20260821-02-pet-points-and-weekly-arena`), การสร้างบทเรียนและแบบทดสอบ (อยู่ใน `20260821-01-lesson-and-quiz-system`), การเพิ่ม/ลบรายชื่อนักเรียน (อยู่ใน `20260821-03-student-identity-and-roster`), รายงานส่งออกและหน้าสำหรับผู้ปกครอง

## Acceptance Criteria

- [ ] ครูเห็นได้ในหน้าเดียวว่านักเรียนคนใดทำแบบทดสอบชุดใดแล้วและคนใดยังไม่ทำ
- [ ] ครูเห็นคะแนนรายคนโดยไม่ต้องเปิดหน้าอื่น
- [ ] ครูเห็นได้ว่านักเรียนคนใดไม่เข้าใช้งานระบบมานานแล้ว
- [ ] นักเรียนที่ครูควรดูแลมีสัญลักษณ์เตือนปรากฏบนแถวของตน
- [ ] ครูกดจากแถวของนักเรียนแล้วไปทำงานต่อได้ทันทีอย่างน้อยคือ ตรวจงาน บันทึกคะแนน และรีเซ็ต PIN
- [ ] ครูเปลี่ยนวิธีเรียงลำดับและกรองข้อมูลได้เอง
- [ ] หน้านี้ไม่แสดงชื่อ-นามสกุลจริงของนักเรียนที่ใดเลย
- [ ] **หน้านี้ไม่แสดงแต้มหรือขั้นการเติบโตของสัตว์เลี้ยงที่ใดเลย**
- [ ] ระบบไม่ส่งการแจ้งเตือนออกไปนอกระบบถึงครู

## ประเด็นที่ยังไม่ชัดเจน (Open Questions)

- **เกณฑ์ของคำว่า "ไม่เข้าใช้งานนาน" คือกี่วัน ยังไม่กำหนด** และยังไม่ระบุว่าครูตั้งเกณฑ์นี้เองได้หรือไม่
- **สัญลักษณ์เตือนมีกี่แบบและแต่ละแบบหมายถึงอะไร ยังไม่กำหนด** (เช่น ยังไม่ส่งงาน / ไม่เข้าใช้งาน / คะแนนต่ำ ควรใช้สัญลักษณ์เดียวหรือแยกกัน)
- **ตัวเลือกการเรียงลำดับและการกรองที่ต้องมีจริง ยังไม่ระบุเป็นรายการ**
- **ช่องว่างข้ามเอกสารที่ต้องปิด:** หน้านี้ต้องใช้ข้อมูล **"เวลาที่นักเรียนเข้าใช้งานล่าสุด"** แต่ `20260821-03-student-identity-and-roster` ระบุไว้ว่าระบบเก็บเฉพาะรหัสประจำตัวและชื่อเล่น ยังไม่ได้ระบุว่าเก็บเวลาเข้าใช้งานล่าสุดด้วย — ต้องกลับไปเพิ่มในเอกสารนั้น มิฉะนั้นฟีเจอร์นี้ไม่มีข้อมูลรองรับ
- **ช่องว่างข้ามเอกสารที่ต้องปิด:** `20260821-02-pet-points-and-weekly-arena` ระบุการจับคู่แข่งไว้ 3 แบบซึ่ง**ครูเป็นผู้จับคู่ทั้งหมด** แต่การตัดสินใจในรอบนี้เปลี่ยนไปเป็น**ให้นักเรียนเลือกคู่เอง** — ต้องกลับไปแก้เอกสารนั้นและแก้ UJ-03 ใน `user-journey.md` ให้ตรงกัน
- ยังไม่กำหนดตัวชี้วัดความสำเร็จเชิงตัวเลข (ยกประเด็นมาจาก Problem Statement ยังไม่ถูกปิด)
