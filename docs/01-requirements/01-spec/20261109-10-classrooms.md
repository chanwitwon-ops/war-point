## บริบท / ที่มา

- เป้าหมายตั้งต้นของโปรเจกต์คือ **ครู 1 คน + นักเรียน 1 ห้อง** (ดู [[20260821-03-student-identity-and-roster|เอกสาร 03]] — การรองรับหลายห้องเรียนถูกระบุว่าอยู่นอกขอบเขต) ระบบที่ deploy อยู่ตอนนี้จึงไม่มีแนวคิด "ห้องเรียน" เลย: ครูสร้างชุดข้อสอบแล้ว**นักเรียนทุกคนเห็นทุกชุด** และไม่มีหน้าไหนบอกครูว่าใครต้องทำ/ใครยังไม่ส่ง
- ผู้ใช้ (2026-11-09): สำหรับการพรีเซนต์ **18 ธ.ค. 2026** ระบบควรรองรับให้ครู**เพิ่มนักเรียนเข้าห้องเรียน** ได้ เผื่อกรณีนักเรียนแต่ละคนอยู่คนละชั้น คนละห้อง และเรียนวิชาไม่เหมือนกัน — เป็นการ**เตรียมระบบไว้เผื่อกรรมการถาม** ส่วนการทดลองจริงยังเป็นครู 1 คน ห้องเดียว
- **แผนสำรอง (ผู้ใช้กำหนด):** ถ้าทำไม่ทัน เดโมใช้ระบบปัจจุบันตามเดิม สมมติเป็นครู 1 คน สอน 1 วิชา มีนักเรียน 2–4 คน

## ความต้องการ (Requirement)

### ก. ห้องเรียนคืออะไร

1. **ห้องเรียน 1 ห้อง = ชั้น/ห้อง + วิชา** เช่น "ป.5/1 คณิตศาสตร์", "ป.6/2 วิทยาศาสตร์"
2. ครูเป็นผู้สร้างห้องเรียน และ**ครูแต่ละคนเห็นเฉพาะห้องเรียนที่ตัวเองสร้าง** (ครูถ้วยไม่เห็น/แก้ห้องของครูจาน)

### ข. การเพิ่มนักเรียนเข้าห้อง

3. **ครูเป็นผู้เพิ่มนักเรียนเข้าห้อง** โดยเลือกจากรายชื่อนักเรียนที่สมัครบัญชีไว้แล้ว และเอานักเรียนออกจากห้องได้
4. **นักเรียน 1 คนอยู่ได้หลายห้องเรียน** เพราะเรียนหลายวิชา (เช่น อยู่ทั้ง "ป.5/1 คณิตศาสตร์" และ "ป.5/1 วิทยาศาสตร์")
5. นักเรียนยังสมัครบัญชีเองเหมือนเดิม (อีเมล/รหัสผ่าน) — เอกสารนี้ไม่เปลี่ยนวิธีล็อกอิน

### ค. ชุดข้อสอบตามห้อง

6. ตอนสร้าง/แก้ชุดข้อสอบ ครูเลือกห้องเรียนที่ต้องทำชุดนี้
7. **นักเรียนเห็นเฉพาะชุดข้อสอบของห้องที่ตัวเองอยู่**
8. **ชุดข้อสอบเดิมที่ยังไม่ผูกกับห้อง:** นักเรียนทุกคนยังเห็นและทำได้เหมือนเดิม (ไม่มีอะไรหายไปหลังอัปเดต) ครูกดแก้ไขแล้วเลือกห้องทีหลังได้

### ง. แต้มและสัตว์เลี้ยงแยกตามห้อง

9. **แต้มแยกตามห้องเรียน** — แต้มของห้องหนึ่งมาจากชุดข้อสอบของห้องนั้นเท่านั้น (ยังใช้กติกาคะแนนรอบดีที่สุดต่อชุดเหมือนเดิม)
10. **สัตว์เลี้ยงแยกตามห้องเรียน** — นักเรียน 1 คนมีสัตว์เลี้ยง 1 ตัวต่อ 1 ห้อง ซื้อ/วิวัฒนาการด้วยแต้มของห้องนั้น
11. **ชุดข้อสอบที่ไม่ผูกกับห้อง ทำได้แต่ไม่ได้แต้มเข้าห้องไหน** — แต้มทุกแต้มมาจากชุดที่ผูกกับห้องเท่านั้น
   - ผลข้างเคียงที่ผู้ใช้รับทราบ: แต้มที่บัญชีเดโมมีอยู่ตอนนี้ (ขวานฟ้า 16 / เหินฟ้า 10 จากชุดเดิม) จะไม่ถูกนับ
12. ทัวนาเมนต์และกระดานเกียรติยศ**แยกตามห้องเรียน** — ครูเลือกผู้เข้าแข่งได้เฉพาะนักเรียนในห้อง และกระดานนับเฉพาะแต้มของห้องนั้น

**หมายเหตุ:** ในกรณีทดลองจริง (ครู 1 คน ห้องเดียว และทุกชุดผูกกับห้องนั้น) แต้มแยกห้องให้ตัวเลขเท่ากับแต้มรวมแบบปัจจุบันทุกตัว

## ลำดับการทำที่เสนอ (ถ้าตัดสินใจสร้าง)

แต่ละขั้นจบในตัวเอง หยุดหลังขั้นไหนระบบก็ยังใช้งานได้ ทดสอบด้วย mock + Rules API ก่อนแตะเว็บจริงทุกขั้น

1. **ออกแบบ** — ยืนยันเอกสารนี้ + แบบข้อมูล/rules (ไม่แตะโค้ด) — ใช้ตอบกรรมการได้ว่าระบบออกแบบไว้ขยายอย่างไร
2. **ห้องเรียน + เพิ่มนักเรียน + ชุดข้อสอบตามห้อง** (ข้อ 1–8) — ไม่แตะแต้ม/สัตว์เลี้ยง/ทัวนาเมนต์
3. **แต้ม สัตว์เลี้ยง ทัวนาเมนต์ กระดานแยกห้อง** (ข้อ 9–12) — เสี่ยงที่สุดเพราะรื้อระบบที่เพิ่งทำเสร็จ ควรทำเมื่อขั้น 2 นิ่งและยังมีเวลา

การเตรียมข้อมูลเดโม (สร้างข้อสอบ/ทำข้อสอบ/ซื้อสัตว์เลี้ยง) ควรรอจนตัดสินใจเรื่องขั้น 3 เพราะถ้าทำขั้น 3 ข้อมูลต้องเตรียมใหม่ในห้องเรียน

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** สร้างห้องเรียน (ชั้น/ห้อง + วิชา), ครูเพิ่ม/เอานักเรียนออก, นักเรียนอยู่หลายห้อง, ชุดข้อสอบผูกห้อง, แต้ม/สัตว์เลี้ยง/ทัวนาเมนต์/กระดานแยกห้อง, ครูเห็นเฉพาะห้องตัวเอง
- **ไม่อยู่ในขอบเขต:** นักเรียนกรอกรหัสเข้าห้องเอง, นำเข้ารายชื่อจากไฟล์/Google Sheets และการล็อกอินด้วยรหัสประจำตัว+PIN (ยังอยู่ใน [[20260821-03-student-identity-and-roster|เอกสาร 03]]), มอบชุดข้อสอบให้นักเรียนรายคน, วันกำหนดส่ง, หลายโรงเรียน, การรวมแต้มข้ามห้อง

## Acceptance Criteria (ร่าง)

- [ ] ครูสร้างห้องเรียนโดยระบุชั้น/ห้องและวิชาได้
- [ ] ครูเพิ่มนักเรียนที่สมัครไว้แล้วเข้าห้อง และเอาออกได้
- [ ] นักเรียนคนเดียวกันอยู่ได้มากกว่า 1 ห้อง
- [ ] ครูเห็นและแก้ได้เฉพาะห้องเรียนที่ตัวเองสร้าง — บังคับที่ระดับ Security Rules ไม่ใช่แค่ซ่อนปุ่ม
- [ ] นักเรียนเห็นเฉพาะชุดข้อสอบของห้องที่ตัวเองอยู่ + ชุดเดิมที่ไม่ผูกห้อง
- [ ] ชุดข้อสอบเดิมที่ไม่ผูกห้องยังทำได้หลังอัปเดต แต่ไม่ให้แต้มเข้าห้องใด
- [ ] แต้มของห้องหนึ่งนับเฉพาะชุดข้อสอบของห้องนั้น (คะแนนรอบดีที่สุดต่อชุด)
- [ ] นักเรียนมีสัตว์เลี้ยงแยกต่อห้อง ซื้อด้วยแต้มของห้องนั้นเท่านั้น
- [ ] ทัวนาเมนต์เลือกผู้เข้าแข่งได้เฉพาะนักเรียนในห้อง และกระดานเกียรติยศแสดงแยกต่อห้อง

## ประเด็นที่ยังไม่ชัดเจน (Open Questions)

- **ยังไม่ตัดสินใจว่าจะสร้างหรือไม่ และสร้างถึงขั้นไหนก่อน 18 ธ.ค.** (ผู้ใช้ขอคุยแผนก่อน)
- เอานักเรียนออกจากห้องแล้ว แต้ม/สัตว์เลี้ยง/ผลสอบของห้องนั้นเป็นอย่างไร (เก็บไว้ซ่อน หรือแสดงต่อ) — ถ้ากลับเข้าห้องได้ข้อมูลเดิมคืนไหม (เอกสาร 03 ข้อ ฉ. ใช้หลัก "ปิดใช้งาน ไม่ลบ")
- ลบห้องเรียนได้ไหม และถ้าลบ ชุดข้อสอบ/ทัวนาเมนต์ของห้องนั้นเป็นอย่างไร
- ชุดข้อสอบเดียวผูกได้หลายห้องไหม (เช่น ใช้ชุดเดียวกับ ป.5/1 และ ป.5/2) — ถ้าได้ และนักเรียนอยู่ทั้งสองห้อง คะแนนนับเข้าทั้งสองห้องหรือไม่
- ชุดข้อสอบเดิม (ไม่มีเจ้าของ) ครูคนไหนแก้ได้บ้าง เมื่อครูแต่ละคนเห็นเฉพาะของตัวเอง
- ครูเห็นชุดข้อสอบของครูคนอื่นไหม
- สัตว์เลี้ยงที่มีอยู่แล้ว (ผูกต่อนักเรียน ไม่ใช่ต่อห้อง) และทัวนาเมนต์เดิมที่ไม่มีห้อง จะย้ายเข้าห้องไหน หรือปล่อยไว้แบบเดิม
- หน้าสัตว์เลี้ยงของนักเรียนที่อยู่หลายห้อง จะสลับดูทีละห้องอย่างไร

## ช่องว่างที่พบ (Gap)

- **G-CR-01 (สำหรับ technical spec):** rules ปัจจุบันให้ครูทุกคนเขียน quizSets / tournaments / leaderboard ได้หมด และ pets ใช้ id ต่อนักเรียน — ต้องออกแบบความเป็นเจ้าของห้อง, id สัตว์เลี้ยงต่อห้อง+นักเรียน และการตรวจว่านักเรียนอยู่ในห้องจริงตอนส่งงาน ใน `sync-architecture` / `sync-api-db` ไม่ล็อกวิธีในเอกสารนี้
- **G-CR-02:** [[20260821-04-teacher-class-overview|เอกสาร 04]] (หน้าภาพรวมห้องเรียน, FE-62 กรองคนที่ยังไม่ส่งงาน) เขียนไว้สำหรับห้องเดียว — ถ้ายืนยันเอกสารนี้ ต้องทบทวนให้เป็นภาพรวม "ต่อห้อง"
