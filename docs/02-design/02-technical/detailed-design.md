- **อัปเดตล่าสุด:** 2026-11-19 — เพิ่ม DD-13 (แสดงแชมป์ทัวนาเมนต์ ผัง/รายการ/การ์ดหน้าหลัก/แชมป์รายสัปดาห์ — AC-FE-31-15~18, ใช้ BR-32/BR-31 เดิม ไม่มี BR ใหม่), เพิ่ม ERR-23 (409 TOURNAMENT_LEGACY ทัวนาเมนต์เก่าดูได้อย่างเดียว) ปิด G-DD-09 และ G-DD-13 (ค) — **ไม่แก้** DD-01~12 ยกเว้นแถว/ข้อ 2.b ของ DD-10 ที่เคยค้าง G-DD-09, ไม่เปลี่ยนรหัส DD/BR/ERR เดิม · (ก่อนหน้า) 2026-11-17 — เพิ่ม DD-10~12 (ทัวนาเมนต์แพ้คัดออก + ครูประกาศผลทีละรอบ: ต่อสู้คู่ API-67 / ประกาศผลรอบ API-69 / ดูผัง+รีเพลย์ตามบทบาท API-66, API-70 + Firestore rules), BR-25~33, ERR-18~22, Security เรื่องผลลับ, Gap G-DD-09~13 ที่มา spec 08 ฌ. + AC-FE-31-3~19, AC-FE-43-1~2 — **ไม่แก้** DD-01~09, BR-01~24, ERR-01~17 · (ก่อนหน้า) 2026-11-11 — แก้ BR-09 ให้ตรงกฎคะแนนทศนิยม/เศษแต้ม (B5): รีเซ็ตแล้ว `available_points = floor(total_earned_points)` (ดู DD-03 reset-pet, หมายเหตุใน DD submit-quiz-attempt) ไม่เปลี่ยนรหัส DD/BR/ERR · (2026-08-25 — เพิ่ม DD-09 (ดูแลสัตว์เลี้ยงประจำวันและค่าความผูกพัน, FE-82/FE-83, API-63 ไม่มี DD/BR/ERR เดิมถูกแก้ไข)
- **ระดับความละเอียด:** Conceptual (pseudo code ระบุลำดับขั้น/เงื่อนไข/ขอบเขต transaction ให้ครบ แต่ไม่ผูกกับภาษาโปรแกรมมิ่งหรือ syntax ของ framework ใดๆ — สอดคล้องกับ [[architecture|architecture]]/[[api-spec|api-spec]]/[[database-schema|database-schema]] ที่ยังเป็น conceptual เช่นกัน)
- **ที่มา:** [[architecture|architecture]], [[api-spec|api-spec]], [[database-schema|database-schema]], [[../../03-testing/01-test-plan/acceptance-criteria|acceptance-criteria]]
- **ส่งต่อไป:** การพัฒนาจริง + [[../../03-testing/01-test-plan/index|01-test-plan]]

รอบแรกครอบคลุมเฉพาะ **8 flow ที่มีการคำนวณ/หักแต้ม/เปลี่ยนสถานะ** ตามที่ผู้ใช้ยืนยันขอบเขต (DD-01 ถึง DD-08) — รอบ 2026-08-25 เพิ่ม DD-09 สำหรับ FE-82/FE-83 (ระบบดูแลสัตว์เลี้ยงประจำวัน) ที่เพิ่มเข้ามาใหม่ — flow อื่นที่เหลือของระบบ (auth, roster, lesson, teacher overview ฯลฯ) ยังไม่ถูกเขียนเป็น Detailed Design ในรอบนี้ และยังไม่มีรหัส DD-XX จอง

รอบ 2026-11-17 เพิ่ม **3 flow ของทัวนาเมนต์แพ้คัดออก** (DD-10 ถึง DD-12) — ระบบส่วนนี้เก็บบน **Firestore และเรียกตรงจากเบราว์เซอร์ ไม่มี server กลาง** (database-schema หัวข้อ 3.1, G-DB-19) จึงเขียน pseudo code เป็น "transaction ของ Firestore + ด่านที่ rules บังคับ" และ status/รหัสข้อผิดพลาดเป็นสัญญาเชิงตรรกะตาม api-spec ข้อ 1.8 · API-68 (ครูชี้ขาดคู่เสมอ), API-64/65 (สร้าง/รายการ), API-71 (ลบ) ยังไม่มี DD ของตัวเอง (ดู G-DD-13)
