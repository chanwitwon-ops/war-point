## ครอบคลุมอะไร

Prototype นี้ครอบคลุมเฉพาะ **UJ-01 — นักเรียนทบทวนบทเรียนและเลี้ยงสัตว์เลี้ยง** (ฝั่งนักเรียนเท่านั้น) ครบทั้ง 8 หน้าจอที่ตกลงไว้ในแผน ไม่มีหน้าจอหรือข้อมูลของครูอยู่ใน DOM เลย (ตาม DESIGN.md ข้อ 4.5)

## วิธีเปิด

เปิดไฟล์ `index.html` ในโฟลเดอร์นี้ด้วย browser ได้ทันที **ไม่ต้อง build ไม่ต้องต่ออินเทอร์เน็ต** ทุกอย่าง (CSS/JS/กราฟิกสัตว์เลี้ยงแบบ inline SVG) อยู่ในไฟล์เดียว

ด้านบนของหน้าจอมี **"แถบสำหรับรีวิว (ไม่ใช่ส่วนของ UI จริง)"** ให้กดข้ามไปดูหน้าจอใดก็ได้ทันทีโดยไม่ต้องเดินตาม flow จริง — ใช้เพื่อความสะดวกของผู้รีวิวเท่านั้น

## Click-through path ที่แนะนำให้ลองกด

1. **หน้า 1 (ล็อกอิน):** กรอกรหัสประจำตัว `3001` และ PIN `1234` (ตามคำแนะนำใต้ฟอร์ม) แล้วกด "เข้าสู่ระบบ" → ระบบพาไปหน้า 2 อัตโนมัติ
   - ทดลองกรอกรหัส/PIN ผิดก่อน 1 ครั้ง เพื่อดูข้อความแจ้งเตือนแบบเป็นกลาง (ไม่ใช้สีแดง ไม่ใช้ถ้อยคำตำหนิ)
2. **หน้า 2 (บทเรียนของฉัน):** กด "เปิดคลิป"/"เปิดเอกสาร" ของบทเรียนใดก็ได้ → แถบสถานะด้านซ้ายเปลี่ยนจาก "ยังไม่ได้ทบทวน" เป็น "ทบทวนแล้ว" จริง ลองกด "ให้ AI อ่านออกเสียง" เพื่อดูปุ่มสลับเป็น "หยุดอ่านออกเสียง" จริง จากนั้นกด "ไปทำแบบทดสอบ"
3. **หน้า 3 (ทำแบบทดสอบ):** เลือกคำตอบให้ครบทั้ง 5 ข้อ (ลองตอบถูกทุกข้อเพื่อดูคะแนนเต็ม 20/20 หรือตอบผิดบางข้อเพื่อดูคะแนนที่คำนวณจริงจากจำนวนข้อที่ถูก) กด "ส่งคำตอบ" → เห็นคะแนนจริงที่คำนวณจากคำตอบ ไม่ใช่ค่าคงที่ กด "ดูผลคะแนน"
4. **หน้า 4 (ผลคะแนน):** สังเกตยอด **สะสมรวม** และ **ที่ใช้ได้** ที่แยกกันชัดเจน กด "ไปดูสัตว์เลี้ยงของฉัน"
5. **หน้า 5 (สัตว์เลี้ยงของฉัน):** ถ้ายอดที่ใช้ได้ ≥ 30 แต้ม จะกด "ปลดล็อกขั้นถัดไป" ได้จริง (หักแต้มที่ใช้ได้ ขั้นเพิ่มขึ้น 1 ยอดสะสมรวมไม่เปลี่ยน) ถ้าแต้มไม่พอจะเห็นข้อความเป็นกลาง ไม่ใช้สีแดง — ถ้าต้องการแต้มเพิ่ม ให้กลับไปหน้า 3 แล้วกด "ทำแบบทดสอบใหม่อีกครั้ง" เพื่อจำลองชุดถัดไป
6. **หน้า 6 (ร้านของแต่งตัว):** กด "ซื้อ" ของแต่งตัวชิ้นใดก็ได้ที่มีแต้มพอ → แต้มที่ใช้ได้ลดลงจริง ของที่ซื้อแล้วไปโชว์ในหน้า 5 ("ของแต่งตัวที่ใส่อยู่") และค่าพลังไม่เปลี่ยน
7. **หน้า 7 (เปลี่ยนชนิดสัตว์เลี้ยง):** กดสายพันธุ์อื่นที่ไม่ใช่สายปัจจุบัน → เห็น modal ยืนยันผลกระทบ กดยืนยัน → ขั้นกลับไปเป็น 1, ยอดที่ใช้ได้กลับมาเท่ากับยอดสะสมรวม (คืนเต็ม), ของแต่งตัวถูกถอด, และมีรายการใหม่โผล่ในอัลบั้มบันทึกเส้นทางการเติบโตด้านล่าง (บันทึกอ่านอย่างเดียว กดเพื่อสลับกลับไปใช้ตัวเก่าไม่ได้)
8. **หน้า 8 (อารีน่า):** เลือกคู่แข่ง 1 คน กด "ยืนยันคู่แข่ง" → เข้าสถานะ "รอครูประกาศผล" กด "ดูผลการแข่งขัน" → เห็นผลชนะ (ได้ดาว) หรือยังไม่ชนะ (ข้อความเป็นกลาง ไม่มีผลเสียใดๆ) ลองกด "เลือกคู่แข่งใหม่" เพื่อจำลองสัปดาห์ถัดไป และลองเลือกคู่แข่งที่ขั้นสูงกว่าเพื่อดูว่าแพ้แล้วแต้ม/ขั้นไม่เปลี่ยนเลย

## ข้อจำกัดของ Prototype

**สิ่งที่จำลอง (mock) ไว้:**
- การล็อกอิน/ล็อกอาต์ทั้งหมดเป็น client-side ล้วนๆ ไม่มี backend จริง ข้อมูลรีเซ็ตเมื่อรีโหลดหน้า
- "เปิดคลิป/เปิดเอกสาร" ไม่เปิดลิงก์จริง แค่แสดง toast จำลอง (เพื่อรักษาความ self-contained ห้ามมี network request ออกนอกไฟล์)
- "AI อ่านออกเสียง" เป็นการสลับสถานะปุ่ม + toast เท่านั้น ไม่มีเสียงจริง
- คู่แข่งในอารีน่าและขั้นของคู่แข่งเป็นข้อมูลสมมติคงที่ ไม่ได้ดึงจากนักเรียนจริงในห้อง
- ปุ่ม "ทำแบบทดสอบใหม่อีกครั้ง" ใช้ชุดคำถามเดียวกันซ้ำ เพื่อจำลองว่ามีแบบทดสอบชุดใหม่ให้ทำในสัปดาห์ถัดไป (ระบบจริงจะเป็นชุดข้อสอบคนละชุด)
- ผลแพ้-ชนะในอารีน่าตัดสินด้วยค่าพลัง = ขั้น × 10 (ค่าสมมติ) เทียบแบบง่ายที่สุด ยังไม่มีค่าสเตตัส/พลังพิเศษประจำสายเข้าสูตรจริงตามที่ spec ระบุว่ายังไม่ล็อก

**สิ่งที่ไม่ได้ทำในเวอร์ชันนี้:**
- ไม่มีหน้าจอ/บทบาทของครูใดๆ ใน DOM เลย (ตามขอบเขตงานที่ระบุ)
- ไม่มีขั้นตอน "บังคับเปลี่ยน PIN ครั้งแรก" (FE-47) และ "ระบบล็อคเมื่อกรอก PIN ผิดหลายครั้ง" (FE-48) เพราะไม่อยู่ใน 8 หน้าจอที่ตกลงไว้ของรอบนี้
- ไม่มีแบบทดสอบชนิดใบงาน/แนบชิ้นงาน (FE-13/FE-14/FE-17) เพราะหน้าจอที่ 3 ที่ตกลงไว้ระบุเฉพาะ "ทำแบบทดสอบปรนัย"
- ไม่มีโหมดฉายผลการต่อสู้ในห้องเรียน (FE-43) หรือโหมดที่ครูจับคู่ (FE-28/FE-29/FE-30) เพราะเป็นฝั่งครูและอยู่นอกขอบเขตของ UJ-01 ฝั่งนักเรียน
- ไม่มีระบบส่งออกคะแนน (UJ-04) และหน้าภาพรวมของครู (UJ-02/UJ-03) เพราะไม่อยู่ในขอบเขตของงานนี้
- หน้าผลคะแนนแสดงเฉพาะจำนวนข้อที่ตอบถูกโดยรวม ไม่มีการเฉลยทีละข้อว่าข้อใดถูก/ผิด (เพื่อไม่ต้องออกแบบกลไก "บอกเฉลยแบบเป็นกลาง" เพิ่มในรอบนี้ — ถ้าต้องมีการเฉลยทีละข้อในเวอร์ชันจริง ต้องออกแบบเพิ่มโดยห้ามใช้สีแดง/ไอคอนกากบาทตาม DESIGN.md ข้อ 4.1)
- ยังไม่ได้ผ่านการรัน `prototype-auditor` เพื่อตรวจ contrast/tap-target/สิทธิ์ตามบทบาทอย่างเป็นทางการ — ต้องรันตรวจก่อนถือว่าปิดงาน
